THE DESIGN (step 2)
==================================================================================================================
(a) THE PHASE SIGNAL [measured inputs, inferred choice].  The why-probe (phase_probe/NOTES.txt "WHAT WAS MEASURED" 1-4)
    found the four gated terms worth 0.17-0.23 of return-to-go at matched posture between steps 50-200 and the settled
    bin, the tail angle a clock (AUC up to 0.95), and a phase-aware TD(0.95) value giving the tail about 0 per degree
    (verify_why).  PR655 sec. 6.2 item 2 (l804) independently calls the step-200 switch "guaranteed" aliasing (main has
    only the width term; this run branch has four), sec. 1.3 measures the reward by window (0-50 3.489, 50-200 3.692,
    200-1000 3.816 per step on main) and sec. 1.4 / l183 / l229 the settle (KE peak step 15, quiet by steps 155-190;
    neck / head sag +12.26 / +12.63 deg, settled by about step 130, sec. 1.2 l129 and sec. 1.5 l212).  The three features:
      settled  is exactly the gate of the observation's own reward (k >= 200);
      discount is the weight with which the gated stream enters V(k) (V(k) ~ A + R(k) B / (1 - gamma) for the gated
               part), so the critic can represent the gate's value effect with one first-layer direction; it is the
               why-probe's pre-registered phase control;
      ramp     is a linear clock over the pre-settle window, where discount is near 0 (0.018 at k = 0, 0.13 at k =
               100) and settled is constant: it lets the critic separate the pop (0-50) from the quiet settle (50-200),
               the other phase effect PR655 sec. 1.3 measures.
    Beyond k = 200 nothing in the reward depends on the episode step (the 1,000-step limit is bootstrapped by SB3: PR655
    sec. 6.2 item 4), so all three are constant there.  k is the counter the gates read (no separate clock to drift).
    NOT addressed: the unobserved action / filter history (PR655 sec. 6.2 item 3), the second hidden variable (O1).
(b) THE ACTOR UNCHANGED [measured]: the mask sets the normalised slots to 0.0 on a clone before the policy MLP; every
    actor path (get_distribution, forward, evaluate_actions, MirrorKLPPO's mirrored KL; SB3 2.9.0 policies.py l646-651,
    l731-736, l751, MlpExtractor.forward torch_layers.py l250-255) reaches forward_actor.  The slots' running mean in the
    start pkl is exactly 0.0 (validate/logs/inspect_start.out), so the actor always saw 0.0 there: V1 bitwise; the input
    is a constant, so the gradient on policy_net.0.weight[:, 60:63] is exactly 0 (unit test; V5: 0.0); their Adam moments
    are 0 and stay 0 (V5), so those columns never move (V2: unchanged on 31/31; V5: bitwise after a step).  The actor's
    parameters are not edited at all (its slot columns stay at their nonzero start values, dead behind the mask).
(c) THE CRITIC AT THE LOAD = THE START PAIR'S [measured]: value_net.0.weight[:, 60:63] := 0 (start max |w| 0.2442; the
    parent's critic multiplied them by a constant 0.0 input, so zeroing changes no value on any input with zero slots)
    and from then on any phase input adds exactly 0: V1 bitwise at 10 phase values; V2 values / advantages identical to
    control's on 31/31 rollouts.  Their Adam moments were exactly 0 (checked at install; refused otherwise), as the
    widen precedent's padded moments are.  From the first optimizer step on the columns learn (V5).
(d) EVERY PATH [measured unless marked]:
    rollouts      the training envs' observations carry the phase (incl. the time-limit terminal observation, k =
                  1000, which SB3 bootstraps through predict_values: unit test on the real env); the buffer check
                  (evidence) proves each row's slots equal the counter's phase exactly, on every rollout;
    train()       evaluate_actions / predict_values see the buffer's slots (the same normalised values); MirrorKLPPO's
                  mirrored observations o[:, perm] * sign keep the slots (perm identity, sign +1 after the hook; the
                  mirrored critic would otherwise see -phase in v_y / yaw_rate); its tensors are built at the first
                  train() from the new map (evidence: mirror_phase_tensors_ok when built);
    VecNormalize  decision: the slots are NOT running-normalised.  At the load they are reseeded to mean 0 / var 1 (main's
                  invariant-8 rule: a slot constant zero for 4.19M samples has var 2.38e-11 [measured], so a phase of
                  1.0 would normalise to 1e4 and clip at 10); after every update they are put back to (0, 1) (a class
                  swap on the SymmetricRunningMeanStd instance; the per-dimension arithmetic of the other 60 dims and
                  the shared count is unchanged: unit test against a control statistics object; V2 identical outside
                  the slots).  So the critic receives f / sqrt(1 + 1e-8), which is f exactly in float32 for every k
                  (unit test).  Frozen rather than updating: the phase is bounded and pre-scaled, updating would make the
                  critic's phase input drift with the running count (non-stationary), and a fixed transform keeps the
                  rollouts, train(), the probe, the reader and the saved pkl on one scale.  It pickles and deep-copies as
                  the stock RunningMeanStd (the saved pkl and the eval env's copy carry the (0, 1) slots);
    eval callback evaluation is the actor only (no predict_values in the code's evaluation path: grep, only the probe,
                  MirrorKLPPO and policy_loading call the critic); the eval env is left as is (its slots stay the
                  zero command), so the ledger is produced as in control: V2 ledger identical to control's;
    the probe     its bank (built on its own env, not swapped) is recorded as built, so the 256 seeded rows <= S are kept;
                  per row the critic is fed phase(kept step + 1) (the kept observation after step index s has counter
                  s + 1: statue_settled k = 200, statue / leans k = 600, the -0.05 lean k = 401; all settled); recorded in
                  run_meta probe_phase and the markers; V2: bank actions and values identical to control's;
    the reader    a critic_phase run's pairs are read with the actor's mask and the critic fed each state's phase: REF k
                  = 200 (settled), OWN the snapshot's counter (500-1000, settled), ON-POLICY each state's counter recorded
                  during the collection; "settled" feeds (1, 1, 1) to all, "raw" zeros (no phase input); at the start
                  copy (S) the arm's load transform is applied first (the run folder holds the parent's bytes), later
                  pairs must carry the (0, 1) slots (else refused); the cache key form "phase" / "phase_S".
(e) CONTROL UNCHANGED [measured]: install_arm("control") changes nothing (BS2's check: params, Adam and VecNormalize
    digests equal before / after the hook); control's StopAtEnd gets no rollout_start; its probe is only checked;
    V1 digests = BS2's V1 digests; V3 control at S = the parent bit for bit.  Evidence additions are read only.
WHY THE SLOTS AND NOT A WIDENING [inferred from code read; PR655 sec. 6.4 l854+]: a 63 -> 66 observation changes the
    observation space, so the run's same-stage resume would refuse the start zip (check_for_correct_spaces; PR655 sec. 6.4
    constraint 1: "it must go through the identity and widening path, or the load is refused"), the start pair would have
    to be rewritten (not FMAN's bytes any more), the MirrorMap file is validated against the plant's widths and the probe's
    bank is 63 wide.  The command slots are already part of the network (first-layer columns exist, never trained, Adam
    moments exactly 0) and carry exactly 0.0 in stance, so using them is the widen precedent's zero-column rule without a
    width change, every other file stays the run's, and each piece is checkable at load (refused otherwise).  The cost: the
    slots are only free while the command mode is "none" (every committed stage today: PR655 sec. 6.4 l869); a product
    version would widen per main's precedent (O2).
