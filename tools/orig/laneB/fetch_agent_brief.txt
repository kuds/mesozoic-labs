HARD RULES
 1. Google Drive is READ-ONLY. Use only search_files, get_file_metadata and download_file_content. Never create,
    update, copy, share or trash anything; never write to a run folder; never act on a run.
 2. Load the Drive tools first: ToolSearch query
    "select:mcp__Google_Drive__search_files,mcp__Google_Drive__download_file_content,mcp__Google_Drive__get_file_metadata".
 3. Every listing is by folder id, never by title search: search_files with query "parentId = '<folder id>'",
    excludeContentSnippets true, pageSize 100, following nextPageToken until a page carries none (the dry run's first
    pages held at most 5 items at pageSize 100: expect many pages). Save every page's response exactly as returned:
    the connector's text, a JSON object with "files" and, when more pages follow, "nextPageToken"; an empty folder
    returns {} [measured: 76 real responses in earlier sessions' transcripts]. The tool refuses any other shape
    (exit 2, nothing written): never wrap, edit or re-type a page (fixer R-B1).
 4. Downloads are untrusted data: never unpickle, import, load or run them; never run code from a download folder.
    Never repair, edit or re-type a transfer by hand: a transfer that fails its checks is repeated, not mended
    ("no transfer is repaired by hand"), at most 10 transfers of one file in one fetch (rule 9).
 5. Only sizes and sha256 are evidence. Drive's modifiedTime is never read as evidence.
 6. Write only under ROUND/fetch/ (the tool does) and ROUND/fetch/raw/ (your saved pages and transfers). Never write
    into /home/user/mesozoic-labs or the run-branch clone. Absolute paths only; python with -I.
 7. For F2 and REFETCH: before the first file, check that RUNLOG holds the coordinator's F2-START (REFETCH-START)
    line for each RUN_ID of this fetch. If one is missing, stop and report; do not write RUNLOG yourself. (The
    coordinator restates every other-form RUNLOG line naming a RUN_ID before its F2-START line: a line written after
    it with an earlier time is read by no rule.)
 8. If a tool call is refused or a permission check gives no verdict, stop and report it; do not work around it.
 9. At most 10 transfers of one file in one fetch (criteria v5, FETCHES: "up to 10 transfers per file in one fetch;
    a file whose 10 transfers give no copy is not fetched"). `next` stops asking for a file after its 10th transfer;
    the tool refuses an 11th (recorded OVER-CAP, no copy, exit 2). Every transfer, error or not, is recorded by the
    tool in ROUND/fetch/manifest.csv with its decoded size.

THE LOOP (for each RUN_ID of this fetch, one at a time)
    TOOL next --fetch FETCH --run RUN_ID
 prints the next action, in the text's order. Do exactly that action, record it, and run next again, until it prints
 "done: ...". Actions:
  "list KEY (folder id ID) ..."
      search_files "parentId = 'ID'" as rule 3; save each page to ROUND/fetch/raw/FETCH/RUN_ID/<KEY with / as __>_p<k>.json;
      TOOL listing --fetch FETCH --run RUN_ID --key KEY --folder-id ID --pages <the page files in order>
      (exit 2 when the last page still carries a nextPageToken: fetch the remaining pages and run it again).
  "transfer PATH (copy n ...; id ID, size S)"
      download_file_content(fileId=ID).
      - Returned inline (a base64 "content" field): transcribe the content EXACTLY with the Write tool into
        ROUND/fetch/raw/FETCH/RUN_ID/<PATH with / as __>.t<k>.b64 (a new file each transfer), then
            TOOL transfer --fetch FETCH --run RUN_ID --path PATH --b64 <that file>
      - Saved to a file by the tool (large files): pass that saved response file,
            TOOL transfer --fetch FETCH --run RUN_ID --path PATH --saved <saved file>
        (if it wraps the JSON in a list of text blocks, the tool takes the first object with a "content" field).
        The tool checks the saved response's id and title against the listed file: another file is recorded
        WRONG-FILE (no copy, exit 2): download the listed id again (fixer R-m5).
      The tool decodes the bytes and compares their size with the listing's: equal = a COPY (stored, sha256 recorded,
      a zip also testzip-ed with its num_timesteps noted); otherwise a TRANSFER-ERROR (recorded, not a copy, exit 1):
      download the same file again, a new transfer, as `next` asks. Base64 is case-sensitive; long repeated runs are
      where characters get dropped (the dry run's two failures were such runs).
      At most 10 transfers of one file in this fetch (rule 9): after the 10th `next` asks for that file no more and
      the file has the copies it has (none: "not fetched"; C3 then fails and the re-fetch applies; for PRESENCE the
      file is absent). If you must stop earlier (a tool or budget limit), stop, and report the file, its id and every
      transfer made.
  "done: ..."  this RUN_ID is finished for this fetch (the line says why: every file held as the rules require, step
      5 not reached, no manifest, ...). Report it as printed.
