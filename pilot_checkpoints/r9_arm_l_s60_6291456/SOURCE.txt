Walking pilot parent checkpoint (never merged; this directory exists only on the pilot branch)

What it is
  The T. rex stance policy "r9 arm L, seed 60, 6M": periodic checkpoint 6,291,456 of the r9 arm L symmetry-screen
  run sym_lean_settled_s60 (physics r9, policy interface r15), with its VecNormalize sidecar. Arm L: mirror-symmetric
  PPO (kappa 0.3), the lateral lean term (weight 0.25, tolerance 0.015 m) and the settled leg target, trained by the
  screen's scratch harness (head 964b7075: e3cf5216 plus one scratch commit whose experiment_* env keys implement the
  lean term and the settled target). Not certified: no gate verdict exists for it.

Why this one
  The pilot's parent is fixed by the r10 screen's rule (foot/r10screen/criteria.txt, "What follows"). If the screen's
  K1-K4 all hold, the parent is the best r10 arm L 6M checkpoint (r10 only) and this checkpoint is not used. Only if
  any of K1-K4 fails is the parent the best of the six 6M arm L checkpoints (three r10 on Drive, three r9): the most
  clean stance_quality/v2 panel episodes (seeds 3042-3081), ties broken by fewer noise falls (joint-space +
  own-sigma). Among the three r9 checkpoints this one is first (40/40 clean, 6 joint-space + 0 own-sigma noise falls;
  s52 38/40, s42 29/40), so it is the r9 candidate in that fallback; it is the parent only if the screen fails and no
  r10 checkpoint ranks above it (40/40 clean with at most 5 noise falls ranks above; 40/40 with exactly 6 is a tie the
  rule does not break, and so is 40/40 with its noise falls unmeasured: an unmeasured count cannot win or lose the
  tie-break, so no parent is chosen until the maintainer decides).
  On a passing screen the screen's text says only "the best r10 arm L checkpoint". The pilot reads that as the 6M
  checkpoint ranked the same way (most clean, then fewer noise falls); this reading is for the maintainer to confirm.
