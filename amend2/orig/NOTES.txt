WHERE THE BUILD DEPARTS FROM THE COMPUTED DESIGN, AND WHY
1. Blank, not delete. The design says "drops" the line. The tool removes its content and keeps its line feed. The
   scorer prints "RUNLOG line <i>" for every non-note line naming a RUN_ID; deletion renumbers 16 such lines on today's
   RUNLOG (more after F2) and the diff list would no longer show only the deviation [measured: deletion_demo]. Notes
   parsed from the blanked copy equal RUNLOG's notes minus line 902, line numbers included (the tool checks this).
2. "At or before", not "earlier than", the last OFF launch. The pinned rule reads an OFF launch in the opening's minute
   as NOT BLIND (score_pc.blindness: blind iff launch < opening). A same-minute SNAPSHOT left in place would keep the
   last OFF run NOT BLIND in the "as if blind" reading; with "at or before" it joins the dropped set, which then is not
   the pinned line alone, so the tool refuses. RUNLOG has no such line, so the result is the same today [measured:
   test (f) case 3; mutant M4 "strictly earlier" is killed by it].
3. The expected dropped set is a parameter for tests. The default is exactly the pinned line's sha256 and refuses any
   other set, an empty one included (the real RUNLOG must still hold line 902). Tests (b), (c), (e) need "no line
   dropped"; they pass --expect-dropped none and the output then says "NON-DEFAULT ... (synthetic tests only; not the
   round's deviation reading)". Tests (a), (c2), (d), (e2), (f), (g) use the default and the exact bytes of line 902.
4. The pinned bytes are checked through APPROVED: APPROVED's own sha256 is the tool's constant, APPROVED names every
   tool file's sha256, and pins_pc.json must be at APPROVED's sha256 too; so refilling pins_pc.json to match a changed
   tool still refuses [measured: test (f)]. --tools exists for tests (a copy of the pinned folder); its files must still
   be at APPROVED's sha256.
5. The tool always runs both readings and prints the pinned one first (the design's "when both are run"): there is no
   deviation-only mode, so the deviation never appears without the reading of record above it. Exit code = the pinned
   run's; refusal = 3; scorer input error = 2.
6. One more line differs after F2 than the design expected: C1's printed value for stance7_r10LTSBpc_s60 lists the
   run's note lines ("lines": {...}), which in the pinned run include line 902 as "SNAPSHOT". C1's verdict reads only
   launches, launch-check stops and actions, so C1's status is unchanged [measured: synthetic tests (a), (c2): exactly
   this listing differs besides the blindness lines]. The tool labels it "C1's listing of the run's note lines without
   dropped line 902" and counts any other difference as UNEXPECTED.
7. The containment is checked twice: the tool lists every file under --round and --tools (size, mtime) before and
   after the scorer runs and prints CONTAINMENT lines; test (g) hashes every file under the test folder, ST/tools,
   ST/amend2/tools and the tool's folder. No read-only round view is needed for real use (the scorer writes nothing
