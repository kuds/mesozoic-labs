0. IN PLAIN WORDS

- The rule. THE ONE TEST compares the three phase-critic (PHASE) runs with the three concurrent switch-off (OFF) runs.
  It is only fair if the people starting the OFF runs had not seen any PHASE results yet; otherwise what they saw could,
  even without anyone meaning it, shape how the controls were started. The pinned rule does not try to judge whether a
  look mattered: any look at a PHASE run's results before the last OFF launch (an F2-START, REFETCH-START or SNAPSHOT
  line of a PHASE run) makes every OFF run launched after it NOT BLIND, and a NOT BLIND OFF run counts in THE ONE TEST
  as missing, at -infinity (criteria.txt lines 297-302, 352-373). A missing run always counts against the hoped-for
  result, so THE ONE TEST can then never read LOWER.
- What happened. At 17:44 UTC on 2026-11-01 the maintainer pasted the s60 PHASE run's notebook output into the chat to
  ask whether more results should be in the run folder (RUNLOG lines 902-903). It held rewards, episode lengths,
  distance and the checkpoint choice; no tail command, TD or ledger figure (RUNLOG line 902) [measured: RUNLOG text; what
  was on screen is the operator's record]. That is an opening under the rule, and it came before the three OFF launches
  (18:12, 18:20, 18:56 UTC). So under the pinned reading all three OFF runs are NOT BLIND and THE ONE TEST cannot pass,
  whatever the TDs turn out to be (p >= 11/20, criteria.txt lines 297-302; p = 20/20 when the three PHASE runs are
  complete) [measured: the dry run on RUNLOG reads all three OFF runs NOT BLIND; the p values on synthetic test (a)].
- "Report only" looks. criteria.txt allows report-only looks at a run (SNAPSHOT lines that decide nothing) only AFTER
  every OFF run's LAUNCH line is in RUNLOG (lines 370-373). Before that point the rule has no report-only kind of look:
  any look is an opening. The 17:44 look came before the OFF launches, so the pinned rule cannot read it as report only.
  Looks after 18:56 UTC would have been report only and changed nothing.
- The two readings. The pinned reading applies the rule as written and stays the round's reading of record. The
  DEVIATION reading computes THE ONE TEST as if the 17:44 look had not happened, i.e. as if the three OFF runs were
  blind; it is printed second, under its own header, flagged as not the pinned reading. If both read the same, the look
  did not matter to the result. If the deviation reads LOWER and the pinned one does not, the honest summary is: the
  pre-registered test could not be passed because of a procedural slip; a reading decided after the slip, which assumes
  the slip had no effect on the OFF runs, reads LOWER.

3. THE DEVIATION READING, EXACTLY AS BUILT (amend2/tools/score_pc_dev.py)

- Definition. The DEVIATION reading of THE ONE TEST is THE ONE TEST line that the pinned score_pc.py, unchanged, prints
  when it reads a copy of RUNLOG in which exactly one line's content is removed: RUNLOG line 902, the 17:44 UTC SNAPSHOT
  line of stance7_r10LTSBpc_s60, identified by the sha256 of its exact bytes (UTF-8, without its line feed, 873 bytes):
  0e30b26ed0a346dd0bdacd8bfd18f2ff9d5f6f58e492e1cc6e29d29763fbce12. Everything else is as in the pinned run: the same
  round folder, pins, APPROVED, F2 stores, panels, classes, TDs, MISSING ranks and permutation test.
- The dropped set, computed then checked. The tool parses RUNLOG with the pinned parser (r10round_common.parse_runlog)
  and takes every SNAPSHOT note of a PHASE RUN_ID whose time is at or before the last OFF LAUNCH or RELAUNCH note (the
  pinned rule reads an OFF launch in the opening's minute as NOT BLIND, so a same-minute SNAPSHOT is in the set). That
  set must be exactly {the line with the sha256 above}; any other set refuses (exit 3): none, two lines, the line edited
  by one byte, its time moved, a second line in the last launch's minute. A report-only SNAPSHOT after every OFF launch
  is not in the set, stays in the copy and, under the rules, changes nothing. F2-START and REFETCH-START lines are never
  dropped.
- Line numbers kept. The line's content is removed and its line feed kept, so every other line keeps its bytes and its
  line number. The scorer prints "RUNLOG line <i>" for every non-note line naming a RUN_ID; deleting the line instead
  renumbers 16 such printed lines on today's RUNLOG [measured: amend2/dry/deletion_demo/diff_blanked_vs_deleted.txt],
  differences that are not the deviation. The tool re-reads the copy and checks: same line count, every other line
  byte-identical, its notes equal RUNLOG's notes minus the dropped one, no early PHASE SNAPSHOT left.
- The pinned bytes. Before anything is read the tool checks <PCR>/APPROVED at its sha256 (a constant), pins_pc.json at
  APPROVED's sha256, and every pinned tool file (14) at both APPROVED's pins.tools_pc and pins_pc.json's tool_sha256;
  score_pc.py's load closure (complete_r10round, ledger_r10round, pc_common, r10round_common, score_r10round) must be
  among them. Any other byte refuses (exit 3).
- Writes contained. score_pc.py writes only its --json file and standard output [measured: every write call in
  score_pc.py and the five tools it loads; complete_r10round, score_r10round and ledger_r10round write only in their own

  copy of RUNLOG as read and on the deviation copy, with both --json paths inside --out; --out must be new or empty and
  outside the round folder, the tools folders and the RUNLOG folder; the files under --round and the tools folder are
  listed (size, mtime) before and after and must be unchanged; it prints CONTAINMENT lines. No read-only view of the

- Printed, in order: the pinned run's whole output (the reading of record); the header
    DEVIATION READING (flagged; not the pinned reading): THE ONE TEST computed as if the three OFF runs were blind;
    maintainer decision 2026-11-02 13:52 UTC, recorded before F2; the pinned reading above stands

4. LIMITS

- Post hoc relative to the opening: decided about 20 hours after the 17:44 opening, by people who knew what the opening
  showed (rewards, lengths, distance of PHASE s60; no TD). It is not pre-registered relative to the opening; it is fixed
  before any F2 file and before any TD of any run was seen [measured: RUNLOG lines 902, 949; inferred: that nothing
  shown at 17:44 reveals a TD].
- "As if blind" is an assumption, not a repair. The rule exists because a look cannot be shown to have had no effect.
  The deviation assumes the look had no effect on the OFF runs; the support for that is that their launches were fixed
  by procedure and passed their launch checks (section 2) [inferred: the checks cover configuration, not every
  possible influence].
- Do not choose between the readings after seeing them. The pinned reading is the record; the deviation is printed
  beside it whatever either says.
- The one test's power. THE ONE TEST is an exact one-sided permutation test over the 20 ways to split six TDs 3 + 3;
  p = 1/20 = 0.05 only on complete separation (every PHASE TD below every OFF TD); any other placement gives p >= 2/20,
  above alpha 0.05, so even the deviation reading reads LOWER only on complete separation [measured: synthetic tests
  (a) and (e): complete separation 1/20, one OFF TD below the PHASE TDs 4/20]. Under no effect and exchangeability the
  chance of complete separation is 1/20 [inferred from the test's definition]. Every caveat of THE ONE TEST in
  criteria.txt (concurrent control, the within-seed dependence A5, GPU nondeterminism, TD's form chosen with STANCE6's
  values in view) applies to both readings.
- An OFF run that is LOST, not COMPLETE or never launched stays missing (-infinity) in both readings: the deviation
  removes only the opening [measured: synthetic tests (d)].
