EPISODES, SEEDS, ACTIONS
  - N = 32 complete episodes per measured pair: a 4-env DummyVecEnv, the first 8 complete episodes of each env (a
    longer episode never ends the count early; extra episodes of a faster env are dropped), as the why-probe did with
    48.  Why 32 [measured basis + inferred]: the why-probe's 48 episodes gave its phase-error contrast D_err a 95% CI
    half-width of 0.012-0.03 normalised units at every checkpoint (phase_probe/analysis.txt) against bucket errors of
    0.02-0.12; 32 episodes widen that by about sqrt(48/32) = 1.22, still well below the effects of interest, and the
    between-continuation spread (4 per arm) dominates the arm comparison anyway.  Cost [measured, val/explore.out:
    2.15 ms CPU per env step at nice 19 beside the running screen]: about 70-80 s CPU per pair, 9 pairs (8 final + S)
    about 12 min on one core.
  - Seeds: base B = 6271 for every measured pair (common random numbers across pairs): envs 6271, 6272, 6273, 6274
    (create_vec_env seed + rank, then VecEnv.seed(B) for the first reset), torch.manual_seed(6271),
    numpy.random.seed(6271).  The tool's own validations use base 6281 (6281-6284); the why-probe reproduction uses its
    own 7700.  NEW: 6271-6274 and 6281-6284 collide with no seed set named in <PS>/criteria.txt (lines 226-235),
    BS2's criteria.txt, the long_blind criteria drafts, tools and measure scripts, the why-probe (phase_probe,
    verify_why, termination_probe) or the PS / BS2 validations, and appear as no whole number or range member in any
    of their 1,181 text files [measured, val/seeds_check.py -> val/seeds_check.out: RESULT NO COLLISION; its sanity
    rows find every known seed].  The independent check's wider scan (check1/out/seed_scan.out, 46,710 files) found
    one range containing them: the repo's historical zero-action reset-seed survey "seeds 3042-7041"
    (docs/STAGE1_SPLIT_PLAN.md line 1209, and its copies), which is no seed set of any screen, probe or run
    (PS's own evaluation seeds 3901-3931 lie in it too) [measured: that file; the scan's output].
  - On-policy stochastic actions exactly as in training: the read_bs.onpolicy_states / why-probe build (the code
    copy's stance config, create_vec_env with 4 envs (DummyVecEnv, Monitor), the pair's VecNormalize with training
    False (frozen statistics) and norm_reward True, load_sb3_model with the stage's [ppo] kwargs, enable_mirror_kl);
    per vector step the policy's forward (sampled actions) on the normalised observation, clipped to the action space,
    as SB3 2.9.0's collect_rollouts.  The loop steps the inner DummyVecEnv and applies the same VecNormalize object's
    normalize_obs / normalize_reward (its step_wait with training False does exactly this), so that the RAW
    time-limit terminal observation is kept for the phase feeding.  Checked equal (bitwise) to SB3's own
    collect_rollouts on the same seeds (unit test), to read_bs.onpolicy_states' states and k (val/equiv_onpolicy.out)
    and to the why-probe's recorded episodes (val/why_online.out).  No optimizer, no update, no learn(), nothing
    written to a pair.

DEFINITIONS
  - k = the env's own _step_count when the observation is made (0 at reset; read from each env before its step), as
    in bs_common THE PHASE.  Buckets by the k of the state: [0,50), [50,150), [150,200), [200,250), [250,1000].  The
    states are the buffer's states, k = 0 ... 999; the time-limit terminal observation (k = 1000) is not a state
    (SB3 does not store it) and only bootstraps G.
  - G_k = sum_{j=k}^{T-1} gamma^(j-k) r~_j + [time-limit truncation] gamma^(T-k) V(s_T), no bootstrap after a true
    termination (SB3: rewards[last] += gamma V(terminal_observation) only when TimeLimit.truncated).  gamma = the
    training gamma (stage [ppo] gamma 0.98, checked equal to the model's and the VecNormalize's).  r~ = the reward
    as the buffer holds it: VecNormalize.normalize_reward of the env's float32 reward with the pair's own frozen
    ret_rms (clip(r / sqrt(ret_var + eps), +-clip_reward), float32): the critic's own units.  Summed in float64.
    G is computed only with gamma = 0.98 (any other gamma refuses, exit 2).  G is not the critic's training target:
    training regressed V on GAE(0.95) lambda-returns (bs_common ARM_GAE_LAMBDA) under each rollout's running reward
    statistics; G is the Monte Carlo return under the final pair's frozen ret_rms, as in the why-probe (sigma_r 45.36
    at S, 43.90 at BS2 control_2501 E [measured, NOTES O4]).  The report prints this as a caption.
  - V = the arm's own critic in the arm's form, through read_bs's own functions: read_bs.Net (the reader's load of
    the pair) and, for critic_phase, read_bs.phase_prepare (the start transform at S; at later pairs the frozen slots
    are required) and read_bs.with_phase (each state's phase phi(k) in slots 60-62, float32 before VecNormalize's
    normalize_obs, as read_bs.critic_slope feeds it: the "effective" critic of critic form "phase+raw+settled"); the
    terminal observation gets phi(1000).  control: the stock critic ("plain").  (--pair mode also: "blind", BS2's
    critic_blind_tail3 effective critic via bs_hooks.critic_blind_class.)  Report only beside it for critic_phase:
    the same critic with the slots zero ("raw", no phase input), against the same G.
  - The start pair S is read in both forms (plain and phase with the start transform); its critic's phase columns are
    zero after the transform, so the two must give equal V on every state (checked; else a PROBLEM).

STATISTICS (all report only; no test, no p-value, no threshold)
  - per pair and bucket: episodes contributing, states; mean of V - G and of |V - G| over episodes (each episode's
    bucket mean, equally weighted) with the SE across episodes (sample SD / sqrt(n)); the state-pooled means (the
    why-probe's convention; equal to the episode means when no episode falls); mean V; mean G.
  - per arm and bucket: the median over the arm's COUNTED runs of the per-run mean V - G and mean |V - G| (and the
    arm mean); the control-minus-critic_phase difference of the arm medians; per seed, control minus critic_phase
    where both are COUNTED.  S's values printed beside (the common start).
  - Self-checks per pair (PROBLEM -> exit 3): every truncation at k = 1000; k consecutive within an episode; the loop's
    own forward values equal the plain critic's (max |dV| <= 1e-4, batching noise); num_timesteps; markers match;
    the phase feeding: in the phase form, when the critic's phase columns are nonzero (value_net.0.weight[:, 60:63]
    after read_bs.phase_prepare), V with phi(k) must differ from V with the slots zero on some state, and V(terminal)
    with phi(1000) from V(terminal) with the slots zero when an episode was truncated (an exact equality means the
    phase was not fed there).

TAIL EXPLORATION NOISE
  - sigma = exp(log_std) (float32 log_std of the zip's policy.pth, exp in float64) for tail_3 = action 14
    (tail_3_pitch_act) and tail_2 = action 13 (tail_2_pitch_act), at S, at each saved pair and at E, per COUNTED run;
    arm medians per step.  Floor: the policy applies none when it samples (SB3 2.9.0 DiagGaussianDistribution:
    std = exp(log_std); the code copy's MirrorKLPPO uses sigma_floor = 0.01 (stage [ppo] symmetry_sigma_floor) only
    inside its mirror-KL loss, sigma = exp(log_std).detach().clamp_min(sigma_floor), mirror_kl_ppo.py lines 21, 201;
    no clamp of log_std anywhere else in environments/ [measured, grep]).  So sigma is reported as sampled, and beside
    it max(sigma, 0.01), the mirror-KL loss's floored sigma, with a flag when the floor binds.
  - Index check [measured, val/explore.out; re-checked at every run]: the env's MuJoCo actuator order (which is the
    action order: base_env._scale_action maps action i to actuator i's ctrlrange) has actuator 13 = tail_2_pitch_act
    and 14 = tail_3_pitch_act, nu = 15 = len(log_std); both map to themselves in the mirror map (action perm 13 -> 13,
    14 -> 14), so the log_std tie does not involve them.  The tool refuses if the names differ.
