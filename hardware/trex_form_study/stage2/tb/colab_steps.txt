5. IF THE BROWSER SHOWS "DISCONNECTED", OR YOU ARE NOT SURE THE RUN IS ALIVE

   A lost browser does not end a run (expected, not yet seen; see 4.6). First look, do not restart.

   5.1  In Drive open the folder  My Drive / mesozoic-labs / stage2 / runs / <RUN_ID>.
   5.2  If it holds DONE.json: the run is finished. If it holds HALT.json: the run stopped itself and waits
        for me. In both cases: do not resume. Tell me. (After a HALT.json I may ask you to resume: then do 5.4.)
   5.3  Otherwise open STATUS.json and find "written_at". It is a time in UTC (search the web for "utc time"
        to see the present time in UTC).
          Less than 10 minutes old: the run is alive. Do nothing.                      (expected, not yet seen)
          More than 10 minutes old: the run has stopped. Go on with 5.4.
   5.4  Resume. In the same copy of the notebook: Runtime > Disconnect and delete runtime (if it is offered),
        then check the first grey box: every value as before, and now
          RESUME                ticked
        Nothing else changes: same REPO_REF, same RUN_ID, same QUEUE, same BUDGET_STEPS.
        Runtime > Run all. Allow Drive.
   5.5  Expect: lines 1, 2 and 3 as before, and in place of "(new run)" (one line on screen):
              Run directory: /content/drive/MyDrive/mesozoic-labs/stage2/runs/<RUN_ID> (resuming session <k>:
              <job> from <n> steps; <m> jobs done)
        <k> counts the sessions of this run (1 at the first resume), <n> is the newest save on your Drive,
        <m> is how many jobs of QUEUE were already finished. Lines that begin "S2 NOTE:" may stand before it
        (for example "S2 NOTE: LEAD.json: ..." when I have answered a halt): they are for me; nothing to do.
        Then, indented, the trainer's own line:
              <job>: resuming session <j>: <job> from <p> steps
        Its two numbers are the trainer's own and may differ from the line above: <j> counts the sessions of
        this one job, and <p> is the save it really goes on from. <p> is <n>, or less than <n> when this line
        stands before it (the newest save was cut and it uses the one before; that is fine):
              <job>: WARNING: skipping checkpoint <n>: <reason>
        One line needs a second look:
              <job>: restarting <job> from step 0
        It is fine only if the line that begins "Run directory" said "from 0 steps": the run had stopped
        before its first save reached Drive, and only that short start is done again. If that line named any
        other number of steps: stop and tell me. (The program is built to refuse such a start by itself; then
        you read "S2 launch: UNFINISHED: ... was not started", see 6.)
        Then line 4 again, as in 4.5, and the run goes on as in 4.6.
        Tell me the RUN_ID, the <n> it resumed from, and the time.
   5.6  If instead you read (one line on screen):

                                                  versions than the run's; the run is already finished; or it

                                                  answered ("is resumed only on the lead's word"); I then tell
                                                  you to resume (5.4).

                                                  software versions than the run's). Nothing was trained. It
                                                  can go on once I have answered.
