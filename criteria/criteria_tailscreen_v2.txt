COEF, PER BOUND (the rule is fixed now; the numbers are pins written before any training step)
- What the calibration measures (calib_tailscreen.py, a copy of P1's lambda_calib.py procedure; NO optimizer step, NO
  parameter change, nothing saved but coef.json):
  - For each start state (s42, s80): the run's training setup is built exactly as run_tailscreen.py builds it (rep seed 101).
    4 rollouts of 8,192 steps are collected with SB3's own collect_rollouts (stochastic policy, VecNormalize statistics
    updating in memory, GAE computed), with no update in between: the policy parameters and Adam state stay the checkpoint's
    (their digest is checked equal before and after).
  - For each rollout, one pass of 64 mini-batches of 128 (rollout_buffer.get(128), as train() draws them), at ratio 1 (the
    first epoch's situation), advantages normalised per mini-batch as SB3 2.9.0 train() does. Per mini-batch:
      G_pg = d(clipped surrogate) / d(action_net.bias[14]), the policy-gradient pull on tail_3's mean as a parameter;
      G_pen(b) = d(L_B at b, coef 1, on the mini-batch's actual rows) / d(action_net.bias[14]), for b = 0.90 and b = 0.60;
      share of rows with mu[:, 14] > b, for b = 0.90 and 0.60.
    Gradients come from torch.autograd.grad and are discarded; nothing is applied.
  - 256 mini-batches per state, 512 pooled.
- The fixed formula (P1's rule, scoped to one actuator and to the bound b):
      COEF_b = RMS(G_pg) / (2 x 0.11), RMS over the 512 pooled mini-batches (sqrt of the mean of G_pg^2, mean included),
      rounded to two significant figures by Python's format(x, ".2g").
  2 x 0.11 is L_B's pull on bias[14] per unit coef on a mini-batch whose tail_3 means all sit 0.11 above b (P1's reference
  excess, 1.11 - 1.0 [measured, LAMBDA]); for a one-actuator mean-over-rows penalty it does not depend on b or on the batch
  size.
- STATED PLAINLY: neither term of the formula depends on b (G_pg is the surrogate's gradient; the reference excess is 0.11
  above whichever b), so the rule gives COEF_90 = COEF_60 by construction [inferred from the formula]. Both are written to
  coef.json separately and pinned separately; the scorer checks each against the rule. What differs between the bounds is the
  realised pull at the start, which coef.json records per state and per bound:
      realised_pull(state, b) = COEF_b x mean over that state's 256 mini-batches of G_pen(b),
  beside RMS(G_pg) and mean(G_pg) for that state. Expected [measured inputs, inferred result; DRAFT arith.out, dose.json]:
  s42 RMS 0.602 (LAMBDA) -> 2.737; s80 about 0.58 -> 2.66; pooled COEF_90 = COEF_60 = 2.7 (2.6-2.8). Realised pull at 2.7:
  BOUND90 0.064 at s42 (about half the mean outward pull 0.122), 0.001 at s80; BOUND60 1.19 at s42, 0.35 at s80.
- COEF_90 = <PIN: from SCREEN/calib/coef.json>; COEF_60 = <PIN: from SCREEN/calib/coef.json>; coef.json sha256 <PIN>.
  coef.json is written once (refused if it exists) and before any training step.
- Against P1 [inferred]: per unit of tail_3 excess, P1 pulled 41 x 2/15 = 5.47, this rule 2.7 x 2 = 5.4. The rule keeps P1's

   - RAIL: next candidate chosen by the maintainer: the deterministic-state variant (BRIEF 2A), a stronger dose (DEC1 D3(c)),
     or the posture decision (B / C).

   the posture"; both PARKED reads "neither bound moved deterministic play below the line".

parent, criterion or stage config.

Report-only beside the outcome (never in a verdict): per state, whether the arm means of CMD at R1/R2 are ordered BOUND60 <=

RUN HANDLING
- Before the first training step (the pre-training gate, SCREEN/tools/gate.sh, after SCREEN/APPROVED exists): the scratch
  clone is clean at <PIN: scratch commit sha>, a child of cf80ecb1, push URL disabled, and `git diff --name-only
  cf80ecb1..<PIN>` is exactly the two files named above; T1-T7 pass on it (the build-tier tests already in the build, the
  gate-tier tests now; BUILD_SPEC); coef.json exists, follows the rule and was written before this gate; V1 and V2 are done;
  the stack equals the pinned versions; criteria.txt's sha256 equals the one in SCREEN/APPROVED and RUNLOG. run_tailscreen.py
  refuses to train otherwise (no --allow-dirty, no override).
- Each replicate writes only into its own new folder SCREEN/runs/<name> (refused if it exists), with run_meta.json (args,
  arm, seed, coef, b, start sha256, recipe checks, clone HEAD and status, stack versions, criteria and coef.json sha256, start
  and final digests, wall time).
- Panels run on the fourth core, one at a time, as checkpoints appear (nice 19); a panel never touches a run folder.
- Disk: before each wave and each panel, check free space; below 5 GB free, pause (nothing discarded) and tell the
  maintainer. After a panel's row is in panels.csv, its per-step CSVs are gzipped with their sha256 recorded first.
- Durable copy (D8, maintainer 17:46): an orphan, never-merged branch <PIN: durable branch name, e.g.
  claude/handoff-tailscreen> on origin, handoff-style (FILELIST.txt, SHA256SUMS, each file <= 5 MB), pushed from a separate
  worktree (never from the scratch clone, whose push URL stays disabled). It is first created once training starts (after
  approval), not before: the first push carries criteria.txt, APPROVED, coef.json, the scratch commit as a patch file
  (git format-patch cf80ecb1..<PIN>), the tool scripts and their sha256. After each replicate finishes: its run_meta.json,
  progress.csv, telemetry.npz, the R1 and R2 checkpoint pairs (zip 4.03 MB, pkl 5 KB each), every panel's episode_trace.json,
  flags.csv and panels.csv rows. Never merged, never a PR.
- A replicate crash (its own process killed, out of memory, exception before 5,242,880): its folder moves to
  SCREEN/runs/<name>_crashed<k> (never deleted, never read for a verdict); the replicate reruns from the start checkpoint with
  the same seed and arguments; the rerun IS the replicate. Digests at checkpoints both wrote are compared and any difference
  reported (the rerun governs). Three own crashes, or a replicate that cannot run: LOST, declared by the maintainer in RUNLOG.
- SCREEN INTERRUPTED (container or session lost, a whole wave killed, the venv gone): not a crash and never LOST. The decision
  stays incomplete. Inputs are restored from the durable copy by sha256 on a stack equal to the pinned versions; replicates
  whose R1 and R2 panels are in the durable copy keep them; the others rerun from the start checkpoint. If the pinned stack
  cannot be rebuilt, the maintainer decides before anything reruns.
- A panel crash is not a replicate failure: the panel is rerun on the same checkpoint (deterministic).
- A refusal on the replicate's own records (start sha256, recipe check, clone state, stack, coef.json, APPROVED) stops it
  before training; the cause is fixed and it starts again under the same name.
- Reruns for any other reason (a readout, a better draw) are not allowed.

- A decision neither incomplete nor provisional is final and goes to the maintainer at once.

  0.5; with B 0.8 against CONTROL 0.1 it passes with 0.87, 0.7 vs 0.2 with 0.70.

  PARKED, OTHER, s80) only lower these. The two bound verdicts are not independent (shared CONTROL).
