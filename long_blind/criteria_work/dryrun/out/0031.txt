D7 THE READING'S RULES.
   - "Missing never helps the hypothesis": a blind continuation that is not READ TO 12M (STOPPED without a rail, LOST,
     COUNTED but not measured) never counts as off the rail, as a gate pass or as free of a habit; it counts only
     against (NOT READ / NOT MEASURED / NOT SHOWN), and any missing blind continuation keeps lines 3-5 from being read
     (line 2). A rail it showed before it stopped or was lost counts as RAILED (monotone: it can only move a reading
     to line 1, as the round's PRESENCE rule). A missing control makes line 3, which withholds lines 4-5.
   - Line order: an observed blind rail (line 1) is decisive whatever else happened; then missing (2); then the
     control's failure (3); then the best (4) and the rest (5).
   - Q1 counts PARKED as off the rail (the round: PARKED is not RAIL) but keeps it out of line 4: a park means the
     drive came back without saturating, which is not "the effect lasted".
   - Q2 is the round's GATE CLASS; because the certificate counts saturated episodes as hop_or_fall, a blind run with a
     late habit can fail the gate through it: Q2 is not independent of Q1/Q3 (KNOWN LIMITS).
   - Line 4 asks more than the round's POSITIVE (CLEAR and GATE PASS): also no habit elsewhere and no negative tail_3
     drive. s80 was POSITIVE with a neck habit; for this study's question that is a moved habit, not a success.
   - RESUMED continuations count (a resume is outcome-blind: chosen by the records' completeness), flagged in every
     line, with a report-only sensitivity line that treats them as not read.
   - The text of every line is fixed so the scorer prints it verbatim (BS2's practice; its stat check compared the
     line text with the criteria's).

D9 RUN HANDLING WITH THE RESUME. One continuation = one queue entry: the decided attempt plus the rows stitched from
   earlier attempts up to the resume point; CHECK verifies the stitching (the builder's V4). It counts in full. Why
   not treat a resumed run as missing: a crash is infrastructure (out of memory, a kill, a container restart), the
   resume point is chosen by the completeness of the files, not by any outcome, and over a 10 h run a crash is
   plausible; dropping resumed runs would make the reading depend on the machine. Why print a sensitivity line: a
   resumed run is a fresh draw from P (one discarded update), not the uninterrupted run (V4 (e)). The harness's counts
   are kept (3 own crashes -> LOST; an EARLY crash halts; a container restart is not counted).
