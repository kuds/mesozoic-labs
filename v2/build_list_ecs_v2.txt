any real policy. The only runs through learn() are V2's, with the model's train() replaced by a no-op, and they run
before approval only under D2 (a), one process at a time, OMP 1, nice 15. Every file the build writes is under <ECS> =
S2/r10round/ecs. COPY, CLONE, F2, the round's folders, RUNLOG and the main checkout are read only. Short names as
criteria_ecs_v2.txt. "G<n>" is the gap number of HS 10. "TB" = COPY/environments/shared/train_base.py.

4. StopAtEnd (G2), in run_ecs.py
- _on_step returns False when num_timesteps == E (or --until), and sets the flag run_meta records. Every other
  callback has run on that step, so the evaluation and the checkpoint at E exist; no update is made on the rollout
  ending at E (SB3 collect_rollouts returns before train(); HS 4.3). It refuses if num_timesteps ever passes E.

5. NO-UPDATE MODE (for V2 only; never for a continuation)
- --no-update replaces the model's train() with a function that counts its calls and returns; --until STEPS stops at
  that step. The parameter and Adam digests at the end must equal the start's, or it exits 1.

6. <ECS>/tools/read_ecs.py (G4, G7)
- --check <run>: CHECK only. Reads run_meta.json and only the update_timesteps, ent_coef and learning_rate columns of
  policy_probe.npz (allow_pickle False). R4: rows with update_timesteps in (S, T), (T - S)/8,192 - 1 of them, against
  the parent's F2 probe at the same steps (A: float32 equal; B: ent_coef 0.0, learning_rate equal); run_meta: code
  digest, start sha256, arm config, seed, stop reason "end" at E or "collapse" at T < E. Writes <run>/check.json;
  exit 0 pass, 4 fail.
- Full read (refused for a run without a passing check.json, and, outside <ECS>/validate/, until every continuation
  is decided): R1 runs the pinned M5 unchanged ("ledger_r10round.py <ledger> --E <T> --json <out>") and keeps the
  evaluations with timesteps in (S, T]; POSITIVE; first ANY-flagged step; flagged count; ANY and TAIL alarms and TAIL
  flags in the window; C6's failures split into those that count (grid, rows, episodes, "ANY input missing") and
  "TAIL input missing" ones (printed, report only). R2: M6's arrays and std_per_actuator for rows in (S, T). R3: M1's
  m1_summary.json for the end pair. Prints every value with the file and sha256 it came from; exit 0 read, 2 input
  error.

7. <ECS>/tools/score_ecs.py
- Each continuation COUNTED, STOPPED (positive or censored) or LOST from run_meta, check.json, <ECS>/lost.json and R1;
  the two tables as counted and as filled; the exact stratified test, two-sided, in exact fractions (the code of
  <ECS>/v1/table_e_ecs.py, moved into the tool), P_UP and P_DOWN each on its own filled table; the reading line and
  its variants; the per-start notes; every report-only line; PROVISIONAL items; "incomplete" until all 24 are decided.
  Exit 0 final, 3 provisional or incomplete, 2 input error.

8. <ECS>/tools/run_waves_ecs.sh (G8; ported from DD43's tools/run_waves.sh)
- Refuses without <ECS>/APPROVED. A queue in this fixed order, 3 slots at nice 10 (D7): for j = 1..6: s42 A j,
  s42 B j, s80 A j, s80 B j (seed j of each list). The disk floor before each start (pause below it). The process
  table and load logged at each start.
- As each continuation exits: read_ecs --check. A pass marks it COUNTED or STOPPED. A failure renames it
  <name>_void<k> and starts no new continuation (VOID). A non-zero exit, or a half-way folder found at (re)launch,
  renames it <name>_crashed<k> and reruns it with the same arguments; a third crash of its own (a container restart
  not counted) writes it to <ECS>/lost.json.
- When all 24 are decided and none is VOID: R1-R3 for each (M1 end traces 3 at a time at nice 10, --out
  <ECS>/traces/<name>), then score_ecs.py.
- Run under a harness-tracked watcher that reads only the runner's log and is relaunched when it exits (DD43's,
  RUNLOG l565). Logs under <ECS>/logs/; no push, no Drive (D9).

  keys pass; any other difference refused.
- Each preflight refusal; the folder-exists refusal; the no-update mode leaves the digests unchanged; the wrapper
  refuses statistics that differ from the pkl's.
- read_ecs --check on the parent's probe against itself (passes), one changed row (fails), arm B zeros (pass), a

- read_ecs on synthetic ledgers (window edges at S and T, an alarm straddling S, C6 failures of each kind, a TAIL-only

- score_ecs reproduces every cell of TE sections 1-2 and CHK 8, matches a brute-force relabelling of every 6-per-arm
